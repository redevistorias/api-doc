Autenticação

Para a integração de um serviço externo com a API da Rede Vistorias é necessária a utilização de uma API Key fornecida pelo usuário (ou adquirida no cadastro do cliente). Possuindo uma API Key é possível gerar um 'Bearer token' com validade de 24 horas, a contar do momento de sua geração. Este token é obrigatório em todos os requests na API da Rede Vistorias.

Gera o token de acesso

Esta requisição aceita dois tipos de "grant_type":

  • api_key: O token gerado neste tipo de requisição é utilizado para fazer novos pedidos na API (utilizado nas requisições de Pedidos ou Price Preview)
  • client_credentials: Utilizado para cadastrar novos clientes e integrações em nossa API.

Pedidos

A API da Rede Vistorias provê uma forma de serviços externos para realizar pedidos de vistorias. Todas alterações no pedido que sejam relevantes para o cliente serão notificadas por um webhook no endpoint informado no momento da geração da API Key. Cada webhook possui um formato específico para a ação que ele representa.

Cadastra um novo pedido de vistoria na API da Rede Vistorias.

O retorno é o código cadastrado da vistoria, e o preço que será consumido do pacote contratado pelo cliente, em metros quadrados.
No caso do pedido de saída ou de conferência, deve ser informada a inspeção anterior. Isto pode ser feito de duas formas, fazendo o upload de um arquivo (ver Upload URL) ou informando um link já existente, que será processado por nossa plataforma. Para pedidos de aditivo, deve-se obrigatoriamente informar apenas o código do pedido anterior, sendo ele um pedido de entrada ou um outro pedido de aditivo.

Override de webhook: É possível informar opcionalmente os campos webhook_url e webhook_secret para que todas as notificações deste pedido específico sejam enviadas para uma URL customizada, assinadas com o secret informado. Quando presentes, os hooks padrão da integração são ignorados para este pedido.

Webhook

O serviço da Rede Vistorias utiliza webhooks para notificar a ferramenta de integração utilizada pelo cliente sobre mudanças do estado do pedido realizado. Esse webhook deve ter caráter público e é informado pelo usuário do sistema no momento de criação da integração. Os eventos existentes são emitidos sempre para a mesma URL seguindo o fluxo do pedido quando é aprovado, rejeitado, atribuído ou finalizado.

Autenticação de Webhooks

Todas as requisições de webhook incluem um header X-Webhook-Signature para verificação de autenticidade. A assinatura é gerada usando HMAC-SHA256 com a api_key da integração como secret.

Header:

X-Webhook-Signature: sha256=<hash>

Como validar (exemplo em Python):

import hmac
import hashlib

signature = request.headers['X-Webhook-Signature'].replace('sha256=', '')
expected = hmac.new(
    api_key.encode('utf-8'),
    request.body,
    hashlib.sha256
).hexdigest()

hmac.compare_digest(expected, signature)  # True se válido

Override de Webhook por Pedido

Ao criar um pedido, é possível informar opcionalmente webhook_url e webhook_secret para substituir temporariamente a URL e o secret padrão da integração apenas para aquele pedido. Quando presentes, todas as notificações daquele order code serão enviadas exclusivamente para a URL informada, com a assinatura usando o secret informado, ignorando os hooks cadastrados na integração.

Upload URL

A API da Rede Vistorias provê uma rota para upload de arquivos em nossa plataforma, utilizada quando uma vistoria requer uma anterior (caso das vistorias de saída e conferência), podendo ser feito esse upload.

Gera uma URL assinada no S3

Utilizando esta rota, é possível conseguir a URL para upload de um arquivo na nossa plataforma, associando este arquivo a um remote-name, utilizado por outras rotas. Assim, é possível efetuar o upload na plataforma da S3, fazendo uma requisição do tipo PUT na URL gerada, e passando o arquivo na requisição. Maiores informações podem ser obtidas na documentação da Amazon.

Authorization
required
string
Example: Bearer eyJ0eXAiOiJKV1QiL...

Unidades

A API da Rede Vistorias provê uma rota para recuperar as unidades com as quais o cliente possui vínculo. Esta informação (valor inteiro e que, na listagem, se chama "id") deverá ser utilizada na geração de pedido, caso queira identificar a qual unidade aquele pedido pertencerá (franchisee_id).

Recebe uma lista das unidades com as quais o cliente possui vínculo

O retorno é uma lista de unidades, contendo os params "id" e "name", de forma a facilitar a identificação de qual unidade se deseja inserir no pedido (franchisee_id).
